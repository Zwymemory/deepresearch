# 现场展示：三项必须当场证明

本清单用于一次有评审在场的本机展示。演示前可以准备合成知识库、服务和脚本；以下三个观察必须在现场产生新的 `runId`，并让评审看到结果。预先采集的报告用于解释历史表现，不能代替现场运行。当前默认执行器仍是 LangGraph；要展示 RAGFlow + Dify，必须显式启用，并从服务配置与运行事件核对实际路由。

## 展示前冻结与检查

1. 记录 Git SHA、Dify 已发布版本、八份 `docs/kb-project` 合成文档的版本、模型、检索参数和预算。检查 Java、RAGFlow、Dify 与所需数据库的健康状态；不要在评审开始后导入或修改知识库。
2. 打开 `http://localhost:8080/demo.html` 和 Dify Workflow 页面。演示页只使用本机演示 USER 身份，不在投屏中显示 Bearer Token、App Key、环境变量或数据集 ID。
3. 准备三栏现场记录：问题与 `runId`；终态、事件游标和引用；故障动作、时间与恢复结果。保存去敏截图或记录，标明本机时间和代码版本。

## 证明一：完整链路可复现

在演示页选择 Durable Workflow 与知识库检索。先核对服务端 `retrieval=ragflow`、`engine=dify` 配置，再从运行安全轨迹里的 `DIFY_STAGE` 事件验证实际路由；页面目前没有独立的路由配置标牌。现场提出“断线重连时，Last-Event-ID 应如何使用？”，展示新建 `runId`、规划/工具/审阅/合成的阶段事件、最终终态和答案。答案应准确解释本项目的 `<runId>:<eventId>` 游标与 `event_id > cursor` 重放规则。另问“本项目生产环境使用的银行账户号码是什么？”，确认没有编造号码、引用或答案；允许安全的 `INSUFFICIENT_EVIDENCE` 终态。

**通过记录：** 两次新运行均有可追溯 `runId` 与终态；正例事实正确，无证据题没有泄露或捏造内容。模型输出可能波动，现场失败要如实保留，不用事前成功样本替换。

## 证明二：引用来自真实知识块并支持论断

打开正例答案中的 `[来源N]`，向评审展示编号与有序 citation ID 的对应关系。选择至少一条关键论断，现场用当前 RAGFlow chunk 内容核对引用确实存在，且文字支持该论断；同时核对 Java 中本地文档处于有效 `DONE` 状态。回答中的来源数量、顺序和编号须与发布的引用数组一致。再提出“线上 Kubernetes 集群的云区域和生产副本数是多少？请引用项目资料解释能否给出数字。”：如果项目边界文档被检索到，拒答应指出资料没有这些数字并引用该边界文档。

**通过记录：** 正例的每个引用都能回查真实 chunk，抽查的论断得到来源支持；有边界证据的拒答有对应引用。只有“chunk 存在”不能证明论断真实。当前 Evidence v4 的敏感联系方式和 JWT 密钥两题仍可能安全地提前拒答但缺边界引用；若现场出现，应记为严格拒答门禁未通过。

## 证明三：断线、取消与重启后的状态可解释

1. 对一个现场新建的运行，在收到至少两个 SSE 事件后记录最后一个 `Last-Event-ID`，断开连接并用该游标重连。对照该 `runId` 的 Java 持久事件，确认后续事件 ID 严格递增、事件没有遗漏或重复展示。全局事件 ID 可能被其他运行占用，不能把数字不连续直接判为丢失。
2. 对另一个仍执行中的 Dify 运行点击取消，确认 Java 立即停止发布答案；继续查看 `remoteStopState`。只有 Dify 详情实际报告 `stopped` 后，才把 `CONFIRMED_STOPPED` 记为远端停止成功；`REQUESTED` 只表示停止请求已送达。
3. 在可控的新运行中重启 Java，再用原 `runId` 与保存的游标查询状态和事件。接受可解释的完成或失败终态，但不接受丢失运行、重复派发或取消后发布答案。记录恢复耗时、终态和错误码。若现场时间有限，重启场景仍应现场执行，历史日志只用于解释预期边界。

**通过记录：** 游标重连能从持久事件继续；取消后没有答案泄漏，远端停止状态有明确定义；Java 重启后原运行收敛到可解释终态。一次现场成功只证明这些具体故障点，不代表任意断点、跨实例或生产级 SLA。

## 现场结论与后续门禁

按三项分别标记“通过 / 未通过 / 未验证”，附 `runId`、时间、截图或去敏日志，以及失败原因。质量对比另看固定 37 题的采集和人工审阅；不能用单次现场成功推断总体通过率。只有答案事实、严格拒答、引用支持、故障恢复和安全边界共同过关，才评估将 Dify 设为默认执行器。
