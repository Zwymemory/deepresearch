## 2. 审查发现与修复

| 问题 | 修复前实际结果 | 修复及复验 |
| --- | --- | --- |
| 长上下文回退取较旧的四条消息 | 8 条历史的最后一条变成 message-4，message-8 丢失 | 按时间顺序保留最后四条；从运行创建到 Dify 输入均保留最新消息 |
| 快照回退未计算 JSON 转义后的大小 | 引号夹具产生 24902 字符，超过 24000 上限 | 对序列化结果继续收缩；保留完整 JSON、Unicode 和最新消息优先级 |
| 上下文成果复用未检查复查期限 | 记忆 fresh 标签未变，但 due_at 已过，A 仍接受 result_reuse | 按上下文 prepared_at 检查复查期限；实际反例被拒绝 |
| 上下文成果复用未检查已有争议裁决 | B 可以合法保存 contested 研究经验，A 仍接受为 result_reuse | 检查所引用 Claim/Decision 的状态；争议成果不能按结果复用，调查线索路径保留 |

前两项来自原有快照回退逻辑，在新增历史接线后会直接影响模型收到的信息。新增两个 Java 回归先运行，得到 2 个实际失败，再修复至通过。后两项用标准结构有效、B 记录规则允许保存的候选复现，修复前执行侧均接受；它们强调“允许保存研究经验”和“允许复用成果”的区别。

## 4. 冻结内容与剩余边界

冻结 0.1.0 的结构、身份/来源/引用关系、状态语义及离线资格规则，文件摘要在 [freeze.json](../../contracts/agent/v0/freeze.json)。知识实体使用显式项目；旧字符串上下文不能自动获得项目权限或晋升可复用成果。Claim/Decision 内容以不可变 ID 保存，纠正产生新 ID；Evidence/Memory 使用独立修订号。未来服务还须落实事务、认证、适用范围核验及依赖失效。

明确保留以下限制：

- Dify 本地输入接线证明传参；used 仍为 unknown，未做新提示的真实模型质量验收。
- 摘要维护请求已可靠落盘，自动生成 worker 尚未实现；记忆的跨会话存储、检索与删除传播仍属后续任务。
- 本轮所有错误资料与记忆案例都是合成夹具，不是模型已完成自主调查的证据。
- 成果复用规则的通过不能证明结论为真或符合新问题的适用条件；运行服务必须重新检查范围和必要证据。
- JSON diagnostics 从 summaryUsed 更名为 summarySelected；当前前端未使用旧字段，Java 旧访问器保留。外部 JSON 客户端和历史反序列化兼容要在新服务发布前核对。
- 现有 UI、线上部署和原 v15 的质量结论不因本轮离线通过而自动更新。
