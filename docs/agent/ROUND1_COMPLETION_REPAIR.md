# 第 1 轮第二次运行侧修复：标准覆盖与依赖复核

基线 `292c6d83b453ff3f387b20ac6fa7bc3d27cca2b2`，对应统一复审 N1/N2。接口见 [ROUND1_COMPLETION_INTERFACE.md](ROUND1_COMPLETION_INTERFACE.md)。旧 ROUND1_RUNTIME_REPAIR.md 是上次修复的历史记录，本说明补充当前完成判定。

任务保存“核查版本”和“核查每分钟速率”两项标准时，仅核查版本只能完成第一项，报告必须保留速率缺口。每项标准使用 run/task/index/原文生成稳定 ID，动作通过 `criterion_bindings` 选择标准和 Claim；首次 scoped Claim 及调查身份一旦绑定不可改写。同一任务可分别核查不同标准，不再限制为一个调查。额外研究 Claim 可以不绑定，但不能隐式完成标准。

Python 每次动作前及核查后重算当前状态。共享调查出现 contested、insufficient、失败或尚未结算时，所有受影响的标准失效；其他任务标准不会被广播为 done。依赖的活动证明以标准身份、初始范围和当前操作构成快照。前提变化会使已使用它的下游标准 stale；前提后来恢复仍需要重新核查下游。重放原操作保留原依赖快照，不能以重放替代复核。历史证据、成功检查和失败观察保留。

V21 持久化原生标准、不可改写的初始 Claim、当前调查操作及依赖快照。写入沿用租约/取消/终态 fencing，仅当前预留 TOOL 操作可推进调查、绑定标准；标准必须绑定该调查的当前尝试。sidecar 不能删除绑定，也不能把调查指针退回旧已结算操作。原 V17–V20 和冻结 v0 不改。

Java `AgentCompletionService` 独立生成报告目标：读取原生标准，核对稳定身份、范围 hash、最新 B 检查、不可变 Claim/DecisionRecord、实际结算操作及依赖证明。旧 done、跨 task/run 或未知身份、重复 Claim、缺失映射、失败/未完成新尝试、旧检查冒充新操作均不能形成完整成功。合法 refuted 可以满足核查目标。演示计划展示每项标准的未覆盖、待解决和需复核状态；完整报告继续保留全部缺口。

封存时在 run 锁内再次核对目标证明。提交终态也在同一把 run 锁内重新计算目标并与封存报告逐项比较，直到终态更新前保持锁；共享调查在封存后失败时，旧报告不能请求 SUCCEEDED。精确终态重放仍须使用同一报告证明。

稳定身份和结构映射不证明模型选定的 Claim 与标准在语义上等价，也不证明来源诚实或一般事实真值。本轮明确保护已保存标准的覆盖与可追溯性，未建设通用语义裁判；controlled observation 生产能力仍未接通。缺少旧映射时保守未完成。
