# Agent 下一阶段：真实模型与检索联调

状态：用户已授权推送已验收基础，并进入本阶段。以本文件所在已推送提交作为共同代码基线，实施分支在各自交付中记录精确 SHA。

## 目标与边界

验证真实模型能否在已有 Agent 控制下自主选择动作、绑定完成标准、调用知识库和网页工具、保留矛盾与缺口，并在原预算内结束。前一轮指定本地工程门禁已通过，见 `FOUNDATION_ACCEPTANCE_2026-09-30.md`。

本阶段先完成真实联调和必要的接线修复。长期记忆与多 Agent 功能安排在这次验收之后。真实模型调用、公开网页搜索/原文读取和本机 RAGFlow 接口访问在本阶段授权范围内；只使用已有项目凭据和配置的模型，不更换昂贵模型、不购买服务、不输出密钥。

现有演示、Dify、RAGFlow 服务及八份知识文档保持原状。测试使用独立应用和数据库、专用验收会话，限定公开或合成资料。不得把私有用户材料送入外部模型/搜索，也不得将原始含凭据配置或响应提交 Git。

## 并行分工与共享环境

### A：运行与真实模型端到端验收

- 现有运行对话负责；开发模型 GPT-6-sol / xhigh。
- 从已推送共同基线新建 `feat/agent-live-runtime`。
- 拥有隔离应用/数据库/sidecar 的启动、构建身份、认证、端到端验收脚本、模型调用与运行报告。优先复用既有脚本；现有 `accept-agent-round1.py` 仅写入 expected-build-sha，需增加对实际服务构建与隔离环境的核验。
- 应用仅绑定回环地址，优先使用 18080；其他端口先检查占用后分配，数据库与卷用本轮专用名称。不得停止或替换现有服务。A 是共享验收环境唯一管理者，避免两边各建一套服务。
- 准備完成后在本地共享协调目录写 runtime-ready.json：精确代码/镜像身份、应用地址、非敏感配置摘要、服务健康、环境归属及 token 的安全读取方式。文件不得写 token 明文；公开报告只保留可复核且脱敏的元数据。
- A 是本轮真实研究运行的唯一发起者。B 完成来源准备后，按同一候选执行下面的六类场景；记录自主决策与实际工具回执，不能手工指定成功动作序列冒充真实规划。

### B：RAGFlow、网页来源与证据质量

- 现有证据对话负责；开发模型 GPT-6-sol / xhigh。
- 从同一共同基线新建 `feat/agent-live-sources`。
- 拥有检索/原文读取的实服务核验、场景材料与预期、来源报告，以及必要的证据侧接线修复。实际核对搜索回执→来源身份→原文快照→引文位置/哈希→裁决，不只检查链接是否能打开。
- 先独立准备真实公开网页与知识库场景、确认 Tavily/RAGFlow 凭据可用性及原文权限，再接入 A 的隔离应用。不得修改八份现有知识文档；需要合成材料时最多新建一个明确命名的验收数据集和四份短文档，单独记录资源 ID 与归属。不得清理不属于本轮的资源。
- 直接来源探测最多 16 次搜索/原文请求；最多上传/解析四份短文档。避免重复导入和无界轮询，真实嵌入/解析调用如产生用量也须记录。若可以用已有公开验收资料完成，则无需新建数据集。
- 在共享协调目录写 sources-ready.json：来源配置的非敏感引用、场景 ID、公开 URL 或验收文档标识、快照哈希、人工核对预期、真实/合成分类和准备状态。需要密钥时只提供安全读取位置，不把值写入文件。
- B 不另发起一套真实模型研究运行；审核 A 输出的来源与语义结果。A/B 若必须改同一文件，先明确所有权与精确接口提交再继续，不混用未提交工作树。

## 有界场景矩阵

| 场景 | 主要检查 |
| --- | --- |
| 仅知识库 | 实际 RAGFlow 命中、原文读取、标准绑定与可追溯引用 |
| 仅网页 | 实际网页搜索、原文读取，不能因未使用知识库报接口无效 |
| 混合检索 | 两类来源共同进入调查，说明引用顺序与适用范围，不预设渠道真值优先级 |
| 版本或条件不同 | 对齐原文范围；不能用旧快照或抓取时间自动消除反证 |
| 错误资料或矛盾资料 | 寻找反证、补查或保留争议，不能挑支持子集宣布完成 |
| 无结果或证据不足 | 自主改写/补查后诚实停止，保留未覆盖标准与部分成果 |

前三类优先使用真实公开资料；后三类可用明确标识的合成事实卡建立可核验预期。必须分别说明“真实模型+合成资料”与“真实模型+真实来源”，不能据合成资料宣称已证明一般事实正确性。错误资料场景还需人工审核模型是否准确理解原文，不只依赖结构校验。

## 调用与停止预算

- 首批六次研究运行；仅为已定位接线缺陷允许最多两次定向重跑，本阶段总计最多八次。每次调用和重跑都记录，不丢弃失败样本。
- 保持原单次上限：8 次决策、16 次模型（包含核查与重试）、16 次工具（包含发布原文复核）、180 秒。不得为了通过验收增大限制。
- A 串行发起真实研究运行，和 B 的来源探测分别登记用量。最多八次研究意味着最多 128 次模型、128 次工具，B 的直接来源探测另限 16 次；实际调用应尽可能少。
- 同一凭据/端点/基础接线错误连续出现两次，停止继续耗费真实调用，先定位问题。凭据缺失或失效时只报告缺少的变量名，并继续完成独立的验收工具和场景准备；不能填入占位符后宣称联调完成。
- 使用已配置模型及项目原预算。记录 provider/model、响应实际用量和可确认费用；价格或实际费用无法确认时标未知，不凭静态单价伪造账单。
