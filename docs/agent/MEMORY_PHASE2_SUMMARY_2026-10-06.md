# 阶段二：有来源摘要与上下文压缩

2026-10-06。基于阶段一提交 `eb54d9a`，只实现 M2；自动积累（M3）、跨问题召回（M4）及大规模页面创意调整尚未实现。

## 实现

- Java 创建自主研究运行时冻结摘要配置；Python 在初始化后及每次行动后检查是否压缩，后续实际规划消费该输入。
- 默认阈值 16,000 字节、规划输入预算 24,000 字节、最近 2 条记录原样保留、重点摘录至多 1,200 字符。计量为最终规划 payload 的规范 JSON UTF-8 字节，含问题分段；不等于 token、完整 HTTP 请求或费用。
- 旧记录从原始状态重新取材。目标、条件、发现、争议、失败、未完成项及下一步均有原文定位/hash。模型只选择服务器发出的片段 ID，不能编写摘要事实。
- 全部被覆盖旧文本使用可逆字典与重复次数序列进入实际规划输入；重点摘录并不穷尽信息。任意未选中的限制仍可逐字符恢复。当前任务、核查与近期原文继续保留。
- 准入包含完整原文编码，按最贵合法摘录组合预留空间；必要时缩短摘录。无法容纳完整范围时保留原文并明确停止，不能用删约束换取达标。
- `SUMMARY` 使用原有全请求 MODEL/token/成本预算和 claim fence；V24 只增加来源范围摘要表及既有 purpose 值。相同范围不重复调用，重启复用持久记录。
- 生成失败保留仍适用的旧摘要和未覆盖原文；用户修改来源后旧摘要失效。取消、超时、旧 claim、记忆撤销继续沿用原规则。
- 已有会话摘要组件仍用于旧路径；自主研究借用其配置，通过原生预算账本接入新的摘要协调器，避免另发未计量的摘要调用。

## 只读接口与页面

`GET /api/research/agents/{runId}/context-summary`：先校验当前运行归属；他人运行 404；读取不创建研究或调用模型。

返回 `project-context-summary-view/1`，包含 READY / FAILED / NOT_GENERATED、summary、sources、未覆盖 source_ref 列表及 measurement。`planner_input_recorded` 只表示已结算规划记录绑定该摘要 hash，不保证模型理解或采纳。

Claude 在第二版页面原记忆位置新增默认收起的摘要入口，可查看内容、来源、原始记录和实际字节；保持原布局与动画。页面截图使用隔离数据库、受控 provider、合成研究历史；真实模型试验单独记录。

## 来源核对

| 展示内容 | 原记录定位 |
| --- | --- |
| 当前目标 | `question`（服务器问题分段精确复原） |
| 旧目标、完成项、未完成条件、下一步、争议 | `context_snapshot/prior_progress/records/*/snapshot/*` |
| 较早对话与其中限制、争议、失败 | `context_snapshot/recentConversation/0..5`，含原文 hash 与字符范围 |
| 当前任务、证据核查、未解决缺口 | 当前原生任务/packet/investigations，不由摘要宣布完成 |
| 最近修正及记录 | 最后 2 条原文，未压缩 |

验收捕获逐条复原 6 条旧对话并对比来源，核对下一规划的摘要等于只读接口；最终字节数还与实际生产 adapter 请求载荷逐字节一致。

## 验证与限制

最终相关 Python 回归 238 项通过，其中 M2 专项 13 项；最终 M2 原生 HTTP/SQL/重启测试 2 项通过。Java 单元 333 项与隔离原生回归 27 项已通过（此前候选）；摘要及最终 wire 修复后有上述专项复验。
