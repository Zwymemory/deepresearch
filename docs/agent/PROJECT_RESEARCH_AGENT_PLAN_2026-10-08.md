# 项目技术研究 Agent：分阶段实施计划

日期：2026-10-08。状态：**方案与实施准备；功能阶段尚未交付。**

本轮目标来自用户：“替我的项目研究一个技术方案，完成验证，再根据结果调整方案”。本机 Qwen3.5-9B 已开始真实兼容性验证，详见 [本机模型实测](LOCAL_QWEN_READINESS_2026-10-08.md)。本方案是记忆能力之后的新一轮升级，以下阶段编号重新从零开始。

## 一、最终体验与首个验收题

用户在网页选择自己的代码项目，提出目标。Agent 按需读取代码、查询官方资料、比较方案、执行受控实验；观察结果后调整方案，最后交付有出处、有实测结果、有适用边界的中文结论。换会话后能接着失败点或待办继续，知道哪些旧结果还有效。

首个验收题暂定为：

> 为 DeepResearch 设计资料复用与跨次续研方案，减少重复检索；读取当前实现，比较候选方案，验证资料变更和项目隔离，再根据实验结果调整建议。

使用当前项目是为了能核对真实代码与结果。后续注册其他项目后，沿用同一套流程。网页通过后端读取已绑定的目录；浏览器不直接遍历电脑硬盘。RAGFlow 中的官方文档继续提供外部知识，代码项目绑定提供当前实现，两者作用不同。

## 二、可以复用的基础

| 已有能力 | 本轮处理 |
| --- | --- |
| LangGraph 自主循环，包含检索、原文读取、修订计划、核查和结束 | 扩充行动与工具，保留当前循环 |
| Java 管理身份、运行、工具授权、预算、回执、SSE 和持久化 | 新工具也经过这些控制 |
| 历史问答、项目进展、续问上下文、分组摘录 | 增加实验记录及其适用条件 |
| 旧版 `FileReadTool` | 复用路径和符号链接边界设计；增加项目绑定、检索、行号、哈希及运行回执 |
| 现有原文证据链 | 为代码和实验增加明确的来源类型，不冒充网页证据 |

当前自主研究的 `AgentDecision` 只允许 `search/read_source/revise_plan/check_claims/finish/stop_with_gaps`；`check_claims` 核对文字证据，**并不会运行代码测试**。旧版文件工具存在，但没有接入这一自主循环。

现有 `researchProjectId` 是研究档案标识，不能直接当成本地代码目录。新增代码工作区绑定时，必须区分这两个概念。

## 三、阶段安排

### 阶段零：建立可信基线，确定模型分工

**实现内容**

- 固定一个小验收题及测试数据，记录当前工作区内容，保留已有未提交修改。
- 定位上轮遗留的 13 项证据链集成失败，分清实现问题、测试夹具契约问题与环境问题，再分别修复。
- 检查本机 Qwen 的加载、结构化输出、代码理解和反馈修订；结果决定是否进入辅助模型试运行。
- 确定工具合同、运行记录、功能开关和首轮工作顺序。

**通过条件**：相关失败场景重跑通过；原有网页检索、知识库检索、跨会话追问的针对性回归通过；真实模型与模拟测试结果分别记录。

**2026-10-08 状态**：已保存基线与失败清单，并运行 Qwen 小样本实测；当时 13 项遗留失败尚未修复。

**2026-10-09 更新**：主分支整合时已修复证据夹具协议漂移、数据库测试隔离、迁移版本断言及记忆字节统计/状态问题。完整 Maven 验收包含 252 项集成测试，无失败和错误（1 项跳过），见[发布复核记录](../MAIN_RELEASE_2026-10-09.md)。本轮没有新增付费模型质量验收；代码工作区和实验执行等后续阶段仍未交付。

### 阶段一：让自主 Agent 看懂当前项目

**实现内容**

- 为研究档案绑定一个服务端登记的代码工作区。
- 接入三个只读工具：列文件、搜索代码、按行读取文件。
- 每条结果包含工作区、相对路径、行号、内容哈希和读取回执；代码变化后不会沿用旧快照身份。
- Agent 自己选择下一次读取位置，生成当前架构和缺口说明。

**页面变化**：小幅增加“关联代码项目”和文件引用入口，能展开实际读取的文件片段。

**验收**：Agent 定位现有记忆入口和自主循环，至少引用三处实际文件；解释旧文件工具与新自主流程的区别；工作区外文件拒绝读取。没有选知识库时也可以分析已绑定项目。

### 阶段二：让方案接受真实验证

**实现内容**

- 增加验证任务与执行器，先支持登记过的 Java/Python 测试及资料复用实验。
- 将选定源文件及必要的未提交改动复制到隔离目录，以内容清单确定版本。不能只按 Git HEAD 创建工作树而漏掉当前修改。
- 通过结构化参数选择验证配置；执行器生成进程退出码、测试数、输出摘要、耗时和产物哈希。
- 启动、取消、超时和恢复都有记录；恢复时先查原进程与回执，不能盲目重复启动。

**页面变化**：展示“待验证 / 执行中 / 通过 / 失败”，失败可展开简明日志。

**验收**：有一组真实失败测试和修订后通过的测试；运行不能修改用户原工作目录；失败、取消和超时保留部分产物。模型写“通过”不能改变进程结果。

### 阶段三：形成方案—实验—修订的自主循环

**实现内容**

- 方案记录包含假设、候选方案、验证方法、固定的验收标准和当前结论。
- Agent 看到失败回执后，选择补读代码、补查资料、修改实验参数或提出隔离环境中的补丁，再运行验证。
- 沿用已有 `revise_plan`，保存每版差异、原因、依据和待办；用户目标与验收标准不能被静默降低。
- 最多修订轮次、无进展停止、预算不足时保留阶段报告，沿用已有控制并补齐实验消耗。

**页面变化**：展示“初始方案 → 验证发现 → 修订方案”，最终报告先给推荐方案，再给关键结果与待验证项。

**验收**：预设一个明确标识的失败实验，Agent 在获得真实回执后改变行动；同一标准下重跑成功；失败方案仍可查看。不能只按固定成功脚本播放，也不能把本轮最小实验结论推广到整个系统。

### 阶段四：把实验经验变成可复用记忆，并完成网页验收

**实现内容**

- 保存“目标、项目版本、尝试方案、测试条件、回执、失败原因、最终判断、待办”。
- 新会话先检查旧结果的项目权限、相关文件指纹、依赖及验证配置；条件相同才复用，变更只使相关结果失效。
- 内容复用与验证复用分开：读过的原文可以缓存，但旧测试通过不能自动说明新版代码也通过。
- 在这些边界完成后，为整理、分类和候选合并接入可选 Qwen 辅助路由；确定性摘录与去重继续优先使用现有规则。
- 在真实 5173→8080→8091 链路完成一次全流程及新会话续研，保存截图和中文验收记录。

**验收**：同条件第二次研究的重复读取/检索次数低于首次；来源更新会重新读取，相关代码改变会重新验证，切换项目不得复用越权资料；拒绝访问的旧记忆不能进入模型。页面可追溯到代码、实验回执和方案版本。

## 四、第一批实现合同草案

以下名称是待实现合同，不是已有接口。首轮固定版本后，前后端据此开发。

| 对象/入口 | 关键字段与边界 |
| --- | --- |
| `CodeWorkspace` | `workspaceId`、所属用户/租户、名称、服务端登记根目录、可读范围；浏览器提交 ID，根目录不由模型提供 |
| `GET /api/research/code-workspaces` | 返回当前用户可绑定的工作区及可用状态；首轮使用本机配置登记，不开放任意目录注册 API |
| `AgentCreateRequest` 增量字段 | 可选 `workspaceId`、`researchMode=general/project_engineering`；旧请求行为不变；研究档案 ID 继续独立使用 |
| `list_project_files` | 相对路径过滤、分页；输出路径和文件类型 |
| `search_project_code` | 受限检索串、范围、最大结果数；输出路径、行号、片段和哈希 |
| `read_project_file` | 相对路径、起止行；输出带行号片段、完整文件指纹、截断状态和回执 ID |
| `VerificationSpec` | `workspaceSnapshotId`、`profileId`、结构化参数、固定验收标准、超时和产物目录 |
| `VerificationReceipt` | `runId/taskId/experimentId`、输入指纹、执行环境、开始/结束时间、退出码、实际测试数、日志/产物哈希和复用来源 |
| `ProposalRevision` | 前后版本、公开的简短理由、依据回执、待验证项；不存放或展示模型私有推理 |

建议 `inspect_project` 和 `run_verification` 作为新的受约束动作，参数使用独立模型校验。只读工具接入运行级授权与幂等回执，不直接把旧工具暴露为任意文件读取接口。

代码结果与实验结果分别标记为 `project_file`、`verification_run`。现有网页/RAG 证据不变；发布器增加与类型匹配的核验。文件内容中的“测试通过”字样、模型输出或旧记忆都不能伪造验证回执。

首轮来源范围采用明确目录和文件类型，排除凭据、运行私有配置、构建缓存和模型权重。真实路径检查在执行端进行，包括符号链接；代码文件内的指令按资料处理。

工程入口主要涉及：

- Java：`AgentCreateRequest`、`AgentRunService`、工具授权/回执、项目绑定及查询接口、证据发布与数据库迁移。
- Python：`agent_protocol.py`、`agent_runtime.py`、工具客户端、预算账本、检查点恢复和工程报告。
- 执行器：隔离快照、注册验证配置、进程生命周期与回执。
- 前端：绑定入口、文件引用、验证卡片、方案版本和续研状态；由 Claude 在原设计上增量实现，任务说明使用英文。

## 五、模型与现有服务的分工

主 Agent 暂沿用现有 DeepSeek，负责总体规划、方案选择与结果收口；Qwen 先评估有限输入的辅助任务。通过应用代码执行文件读取、测试和权限判断，不能把这些工作交给模型凭文字决定。

现有 worker 使用单个全局模型配置，双模型协作需要新建按角色选择的模型适配，不能只换一个 URL 就声称完成。每次辅助调用记录模型摘要、输入边界、耗时和真实 token；失败时保留错误记录，按剩余预算回退或跳过。打开页面、浏览摘录不触发额外模型调用。

本轮保持 Java + LangGraph 主循环、RAGFlow 检索、PostgreSQL 持久化。Dify 可继续作为固定子流程及对照路径，暂不插入主循环。先把单个主 Agent 的工具与反馈闭环做实，再评估是否需要多 Agent。

## 六、开始实施的顺序与收口标准

1. **基线排障**：从 13 项失败中选最小的正向证据完成场景复现，保留真实报错；修复后回跑相关场景，不能删除失败断言。
2. **工作区合同**：先完成服务端绑定与三个只读工具；覆盖相对路径、符号链接、分页、代码变更和回执对应关系。
3. **自主接线**：模型能选工具并看到真实观察值，发布结果能引用文件与行号。
4. **小幅前端接入**：API 有真实样例之后向 Claude 下发英文任务；每阶段截图对应原生服务数据。
5. **执行与修订**：按阶段二、三完成首次真实闭环，再做阶段四跨会话复用。

每阶段交付：可复现步骤、运行/回执标识、相关测试结果、真实页面截图及精简中文说明。测试不通过时标为未完成；截图仅证明页面表现，完整日志和产物证明执行结果。

新增能力使用独立开关，关闭后仍可使用现有研究/学习流程。验证产物与原工作区分离；首版交付可审查的方案与隔离验证结果，将补丁应用到用户主代码属于后续功能范围。
