# 第 1 轮运行侧修复

基线：`b5ac4ebde13f64e2134b91214d3f72dd3501b9e7`。本说明对应 A 的运行、认证、发布与界面改动，B 的 evidence 实现独立提交，组合验收版本记录在外部 repair-runtime 交接文件中。

## 改动与原因

- 每个原 Claim 集合分别保存调查、原范围、父检查、成功历史与当前裁决。重排 Claim 或换任务不重置已知调查；同一任务改写原范围会拒绝。核查错误和异常只保留为观察，不覆盖成功裁决，也不让依赖任务继续执行。
- 补查读取服务端当前调查，携带其必需旧材料。可以明确选择当前调查的原文；全部材料送交服务端，超出四份由 B 报容量不足并记录失败尝试，不截取最近四份，也不在客户端提前返回而丢失服务端记录。服务端仍独立验证反证连续性，客户端字段不是授权凭据。
- `finish` 与 `stop_with_gaps` 都请求服务端完整报告，无 Claim 选择列表。消费 `report_status` 与 `terminal_status`；`approved` 仅表示这份报告可以封存。已有支持部分及引用保留，未完成目标或争议使终态为 `INSUFFICIENT_EVIDENCE`。
- 发布不擅自把任务改为完成。补查真正解决同调查后更新其已绑定目标，保留旧检查历史。最终报告只消费各调查的当前裁决，不永久累计已解决的历史缺口。
- Java 同时封存精确正文、引用与完整性终态。部分报告和全缺口报告也必须具有发布证明；更换正文、引用或把 partial 改成 SUCCEEDED 都会拒绝。Agent 正文保持原字节，不做 trim 后再验签。
- 原文复核通过原搜索回执精确定位当前 run 的已结算搜索，不使用最新同 sourceId 命中替代旧身份。跨 run 回执继续拒绝。知识库复核仍占用统一工具额度。
- 同来源的多份原文摘录沿用一个引用编号，所有 occurrence 保留。加入界面引用详情后的报告也受统一结果大小限制；超容量明确拒绝，不以删除目标或引用来压缩。
- 界面区分全部完成、部分成果和待核查报告，显示未完成目标数量，并保留原文引用详情。冻结协议与 V17/V18/V19 原样保留；A 不新增迁移，隔离 bundle 采用 B 已公告且已提交的 V20。

## 验证范围

维护中的 Python 回归覆盖独立子问题、重排/改写、错误响应与异常、失败依赖、真实 LangGraph checkpoint 恢复、后续有效解决、材料容量、完整报告终态、stop_with_gaps 保留可靠部分、预算和取消。`wrong-material` 的替身虽然解决了 Claim，却留下新建目标未完成；回归明确要求部分成果，不能据此声称整项完成或真实实验已实现。

新增 `AgentHttpPostgresIT` 使用临时 PostgreSQL、完整 Flyway、真实随机端口 HTTP、API/internal JWT、实际授权与发布/终态链路。只替换 RAGFlow 原文传输、向量能力与模型回执；不 mock JdbcTemplate、身份服务或授权服务。覆盖异主访问、错误 JWT、原回执持续有效、精确终态绑定、全缺口报告、伪造项目/跨 run 回执、租约、取消与统一复核预算。其组合结果须在采用 B 的已提交实现后记录，接口提交不等于实现验收。

正式服务、Dify 发布、密钥、数据卷和八份知识文档不改。无真实模型采样或外部来源调用，受控观察生产适配仍未接通。准确数量与最终版本以外部交接的 `final_sha=tested_sha` 为准。
