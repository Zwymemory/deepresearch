# M1：显式跨会话续研

在保存研究进度的基础上，将所选项目的历史真正传给自主研究规划。浏览器只选择项目与会话；服务器选择、冻结并校验历史。历史是调查上下文，不能作为本轮事实证据或完成证明。

## 使用

1. 使用已有进度接口保存并选择历史项目。
2. `POST /api/research/projects/{projectId}/resume-context` 创建新会话并返回 `project_id`、`target_session_id` 和进度预览。载入及 GET 刷新均不创建研究或调用模型。
3. 单独开始续研，保留返回的项目/会话配对：

```http
POST /api/research/agents
Authorization: Bearer <user-token>
Idempotency-Key: <one-key-for-this-exact-request>
Content-Type: application/json

{"question":"接着做，先推进尚未完成的部分。","sessionId":"<target_session_id>","requestedTools":["kb_search"],"researchProjectId":"<project_id>"}
```

4. 使用 Accepted 的 `statusUrl`、`eventsUrl` 查看过程。连接不明确时使用原请求正文及原幂等键重试。重放复用原先冻结的历史，不重新选取今日内容。

没有 `researchProjectId` 的请求保留原有无记忆行为。普通 durable workflow 入口不接受项目记忆选择。浏览器不能上传 `prior_progress` 或绑定/哈希字段；已关联其他项目的会话不能换绑。

## 输入及有效性

- 选择窗口最多20条，选入最多3份完整快照，总包络最多16384 UTF-8字节；整条超限时省略并记录原因，没有可用快照时拒绝选择。
- Java 在创建事务中保存 `prior_progress` 与 `prior_progress_binding`（项目、投影SHA256、字节数）。Python 的实际规划 payload 为 `agent-decision-context/3`，含独立 `prior_progress`，始终 `trusted_as_evidence=false`。无记忆仍用原版本。
- 模型被要求承接相关待办，保留条件、争议及缺口，区分旧目标和当前问题，不编造测量值。提示在最终规划策略变换之后附加；CHECK 不继承历史作为核查证据。
- 服务身份的 `POST /internal/agent/memory/validate` 检查当前 run/project/session 归属、claim、lease、deadline、grant、取消状态、冻结内容与当前所选记录/现有引用有效性。已领取的 QUEUED run 可做首次检查。
- worker 初次执行、未完成检查点恢复和每次携历史的 DECISION 尝试（包括重试与已结算回放）都检查。检查点与数据库选择不同或缺失时拒绝。已完成图只需原幂等收尾，不再消费历史。
- 删除或修改被检测到后，以 `RESEARCH_MEMORY_REVOKED` 等运行错误结束，提示重新选择。不会静默换快照或退回无记忆。`RESEARCH_PROGRESS_SELECTED` 只证明已选择，不能证明模型已收到或事实已核验。
- 校验等待期间发生取消、claim 变化或超时，保留原有生命周期处理；已过期的选记忆运行以 TIMED_OUT 收尾，不误报记忆失败。

检查与发送非原子；检查之后的变化、在途请求不能撤回。内容哈希无法检测两次检查之间同内容删除/重建或 A→B→A。沿用的引用检查不等于完整远程原文/回执/知识库治理。本阶段不新增许可平台、摘要、自动积累或跨问题召回。

## 验证

使用项目 Python 虚拟环境，避免 Java 子进程误用系统 Python：

```sh
cd workflow-service
uv sync --extra test --frozen
.venv/bin/python -m pytest tests/test_progress_memory.py tests/test_agent_runtime.py tests/test_agent_context_runtime.py tests/test_agent_json_transport.py tests/test_agent_identity.py tests/test_runner.py -q
```

在仓库根目录、Docker 可用时运行隔离 PostgreSQL/真实 HTTP 与 Python 进程验证（不访问付费 provider/外部检索）：

```sh
AGENT_PYTHON="$PWD/workflow-service/.venv/bin/python" mvn -o -q -Pintegration -Dtest=ResearchProgressContextAssemblerTest '-Dit.test=MemoryContinuationIT#crossSessionCreationValidationAndActualPythonProviderWire+processRestartRevalidatesDeletedMemoryBeforeSettledDecisionReplay+expiredSelectedMemoryRunRetainsTimeoutTerminalStatus' verify
```

三个 M1 IT 分别验证完整原生创建/载入/规划/收尾、真正双进程检查点恢复后的撤销拒绝，以及过期运行的原生超时收尾。相关 Python 回归112例通过，其中18例 M1；Java 单元333例与已有隔离集成22例通过。生产 adapter 的 provider transport 明确受控，实验历史和检索数据明确为合成。`target/memory-m1/` 中记录实际模型 wire、动作与原生状态，不保存 Authorization 或模型密钥。

2026-10-06 的单独 DeepSeek 实验总计6次成功 API响应：输入30695、输出2458 tokens。观察到历史延迟待办与限制进入规划；空检索条件下最终原生状态为 INSUFFICIENT_EVIDENCE。未产生实测延迟数据，不能把小样本解释为通用效果提升。API 未返回实际账单金额。前两轮夹具配置/断言失败和最终成功观察分别保留。

页面由 Claude 的第二版前端承接；页面截图的受控 provider 演示与上述真实 DeepSeek 实验分别记录。没有自动合并、推送或部署。
