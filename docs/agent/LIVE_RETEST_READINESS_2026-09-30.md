状态：**仅完成离线准备；旧阶段停机规则仍生效，未发起新研究、搜索、读取、上传或解析。** 本计划使用已审查的六类场景和现有隔离验收环境。知识库闭环已有一次真实成功；仍需复验网页、混合、版本/条件，并首次运行矛盾资料和证据不足。旧六次运行、两次定向重跑及其失败回执必须原样保留。

## 诊断回执准备

既有 `scripts/accept-agent-round1.py` 的受保护审计现在逐次列出模型操作：结果是否可用、输入/输出 token 是否各自已知，以及白名单化的失败类别。`UNKNOWN` 表示结果不可用；若提供方已给出合法 token 数，这些数仍计入实测用量。缺失用量单独计数，数字 0 视为已知，不会误作缺失。新增分类只允许固定 `failure_kind`、`error_class`、布尔 `retryable`、数字 HTTP 状态/工具数和固定字段路径；未识别的元数据、原始响应与异常正文不进入新增导出。历史混合/版本回执没有这些分类，原因仍标为未知，不能用新实现反推。

离线账本测试包含“结果 UNKNOWN 但 token 已知”、完全缺失用量、429 数字状态和恶意原文哨兵；只验证导出与计数，不调用服务或模型。现有 `admit` 闸门、六次初跑/两次定向重跑上限、连续相同基础错误停止规则保持不变。

## 建议补测批次和判据

这是**拟申请**的独立小批额度：最多 **5 次新研究运行、0 次自动重跑**。第一批最多 2 次；只有两例都通过各自语义判据，才进入第二批最多 3 次。每次仍最多 8 决策、16 模型准入、16 工具准入、180 秒，持久化输入/输出 token 上限仍为 64,000/16,384。五次理论上最多 80 模型准入、80 工具准入、40 决策；这不是预计用量或费用。费用只按提供方可确认的实际数据记录，否则标未知。

| 顺序 | 场景 | 人工核对的通过条件 |
| --- | --- | --- |
| 1 | `web-only` | 真实网页原文被读取并形成可追溯引用；注册/转让限制和 HTTP 保障范围均由核查后的网页证据支持。页面修订、抓取时间不进入事实 `valid_at`。完整回答才算通过。 |
| 2 | `mixed` | 知识库资料卡支持文档用途，真实网页原文支持 best-effort HTTP 与生产限制；两类已读原文都进入核查和引用，不能用某一渠道的标签代替原文裁决。 |
| 3 | `version-conditions` | 合成资料中 1.0/legacy 的 10 次/分钟与 2.0/general 的 20 次/分钟分别绑定版本和条件；不能互相推广或靠抓取时间判优先。 |
| 4 | `contradictory-material` | 合成同版本/同条件资料的 5 秒和 7 秒分歧都保留；没有独立消解依据时保留 contested/缺口，不把唯一超时断言当成已证实。 |
| 5 | `insufficient-evidence` | 合成资料没有发布日期时明确留下未覆盖标准与证据缺口，以 `INSUFFICIENT_EVIDENCE` 或等价诚实不足状态收尾；不能从上传/观察时间编造日期。 |

逐例核对实际模型身份、构建 SHA、HTTP/JWT 请求、来源搜索→原文→核查→出版回执、最终状态和预算。`SUCCEEDED` 只对完整且有证据的网页/混合/版本回答成立；矛盾和证据不足的诚实不足结果可满足该场景的验收目标，但不能冒充完整事实证明。结构检查通过仍需人工阅读原文、Claim 及引用。首次失败样本和本批所有运行 ID 都保留，不用新结果覆盖旧账。
