# Original obligations and required-source verification

Fresh runs persist `agent-planning-obligations/3` and `agent-frozen-requirements/2` before their first model call. Initial planning separates substantive factual, inference and genuinely requested recommendation obligations from `source` and `output` constraints. Both `obligations` and `constraints` are required; an unconstrained question uses `constraints: []`. Constraints use exact server segment IDs and obligation indices. The adapter attaches their original text to the relevant canonical requirement anchors and conditions; the native manifest and frozen Claim/DecisionRecord schemas remain unchanged.

Continuation omits both declaration fields and returns the exact frozen manifest hash. Under `agent-obligation-claims/1`, a proposed claim contains only `text`, `requirement_id` and `criterion_id`. The server derives kind and applicability from the same-task registered reference. Unknown, stale, duplicate or foreign references fail with bounded guidance. Canonical claim ordering carries the matching reference with each claim. No old model response is rewritten to pass a scope check.

The existing bounded CHECK call uses `evidence-check/3`. Native authority reconstructs its `original_context` from the settled initial declaration, registered manifest and current criterion bindings, including the complete question and all classified constraints. The request fingerprint binds this context, while the investigation identity retains the original canonical claim so changing a reference cannot fork away from counterevidence. Reusing a call with different context is rejected.

The verifier proposes full-question `planning_alignment`, per-claim `answer_alignment`, and per-original `source_alignment`. Incomplete classification, irrelevant facts, absence of mention and missing required sources cannot complete an obligation. For explicit URLs in source constraints, trusted code compares the restriction with the actual final read locator, including redirects. Search titles and requested candidate URLs do not establish source identity. Named-source interpretation without an explicit URL remains a conservative semantic proposal; `semantic_truth_guaranteed` remains false.

Previously applicable relations retain their direction, exact quote and assessment reference. A later semantic alignment label cannot dismiss retained counterevidence: disagreement remains contested, and changed qualification remains a visible unresolved gap. A page rejected on its first check as the wrong source can still be supplemented with the correct authorized original within existing budgets.

Completed checks carry the verifier response and its request/response hashes bound to the settled CHECK receipt. Native completion, the public evidence view and acceptance capture independently revalidate the declaration selectors, registered context and adopted-source gates. Capture also binds the current criterion to the exact requested claim. Waiting checks remain recorded incomplete; missing completed proof fails closed. Existing planner v1/v2, frozen continuation v1 and CHECK v1/v2 requests and receipts keep their original replay behavior.

No numeric budget, strict JSON cap, hidden repair call, database migration or source-read admission change is introduced. Controlled adapter and HTTP/PostgreSQL tests verify these boundaries. Real model classification and named-source judgement still require independently reviewed live acceptance; controlled fixtures do not prove real autonomy.
